# WordPress 投稿用の設定メモ

本文のファイルは 2 つあります。**どちらか片方を使ってください。中身は同じです。**

| ファイル | 貼り付け先 | 向いている人 |
|---|---|---|
| [`post.html`](post.html) | **カスタム HTML ブロック**（または コードエディター） | まず確実に貼りたい |
| [`post-gutenberg.html`](post-gutenberg.html) | コードエディター | 貼ったあと WordPress 上で編集したい |

### 手順 A：カスタム HTML ブロックに貼る（かんたん・確実）

1. 投稿編集画面でブロックを追加 → **「カスタム HTML」** を選ぶ
2. `post.html` の中身を全部コピーして貼り付ける
3. ブロック右上の「プレビュー」で表示を確認する

記事全体が 1 つのブロックになります。WordPress 側での細かい編集はしにくくなりますが、**レイアウトが崩れる心配がありません**。

> 段落ブロックに HTML を貼ってもタグが文字として表示されるだけです。必ず「カスタム HTML」ブロックを使ってください。

### 手順 B：ブロックに分解して貼る（あとから編集したい場合）

1. 投稿編集画面の右上「︙」→ **コードエディター** を開く
2. 中身を全部消して `post-gutenberg.html` を貼り付ける
3. 「ビジュアルエディター」に戻す

見出し・段落・表・コードがそれぞれ正しいブロックに分解され、**そのあとは普通に編集できます**。`post.html` をコードエディターに貼っても近い結果になりますが、ブロックへの分解精度はこちらが上です。

> クラシックエディタの場合は「テキスト」タブに `post.html` を貼ってください。

### 本文を直すとき

編集するのは `post.html` だけです。直したら次を実行するとブロック版が作り直されます。

```bash
python3 blog/to-gutenberg.py
```

### なぜ Markdown ではないのか

WordPress 本体に Markdown を解釈する機能はありません。そのまま貼ると `##` や `|` が文字として表示されます。プラグインを入れれば書けますが、**表とコードブロックが崩れやすく**、保存時に結局 HTML へ変換されます。画像の `alt` や `figcaption` も細かく指定しにくく、SEO 上そこは落としたくない部分です。

## 5. 画像の挿入（手動）

画像は WordPress 上で手動挿入する前提にしています。`post.html` に **`<img>` タグは入っていません**。
代わりに、**赤い破線の枠**が本文の 5 か所に埋め込まれていて、そこが挿入位置です。
枠の中にファイル名・キャプション・代替テキストが全部書いてあるので、上から順に処理していけば迷いません。

| # | ファイル | 挿入位置（記事内の目印） |
|---|---|---|
| ① | `docs/figures/01-overview.png` | 「実際に何を検知するのか」の表の直後（記事の顔になる図） |
| ② | `docs/figures/02-rules.png` | 「既定のルールセット「Sonar way」…」の見出し直後 |
| ③ | `docs/figures/03-file-map.png` | 同じ章の末尾（「これが「最低ライン」の中身です」の段落の後） |
| ④ | `docs/figures/07-connected-compare.png` | 巻末補足「同じコードでも、見える範囲を全員で揃えられる」の見出し直後 |
| ⑤ | `docs/figures/04-connected-mode.png` | 巻末補足「サーバーが解析してくれるようになるわけではない」の見出し直後 |

### 作業手順

1. 赤枠の中の**キャプションと代替テキストをコピー**しておく
2. 赤枠のすぐ上か下に「**画像**」ブロックを追加して、該当ファイルをアップロード
3. 配置を**中央寄せ・大サイズ**にする
4. コピーしたキャプションを入れ、ブロック設定サイドバーの「**代替テキスト**」に代替テキストを貼る
5. **赤枠のブロックを削除する**（カスタム HTML ブロック／`wp:html` ブロックとして 1 個ずつ独立しているので、まとめて消せます）

`alt` は Google 画像検索の流入とアクセシビリティの両方に効くので、省略しないでください。

**96 / 98 / 101** に修正しています。SVG が正で、PNG は次のコマンドで再生成できます。

```
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
TMP=$(mktemp -d)
printf '<!doctype html><meta charset="utf-8"><style>html,body{margin:0;background:#fff}svg{display:block}</style>' > "$TMP/w.html"
cat docs/figures/03-file-map.svg >> "$TMP/w.html"
"$CHROME" --headless=new --disable-gpu --hide-scrollbars \
  --force-device-scale-factor=2 --window-size=1200,900 \
  --screenshot=docs/figures/03-file-map.png "file://$TMP/w.html"
```

（ImageMagick では日本語フォントを解決できず失敗します。Chrome を使ってください。）

### アップロード時のポイント

- **ファイル名を英数字にする** —— `sonarqube-sonar-way-rules.png` のように内容が分かる名前に。日本語ファイル名は URL が壊れやすいです
- 元画像は幅 2400px（Retina 相当）です。WordPress 側で自動生成される `large` サイズが使われます
- **アイキャッチ画像**には `00-eyecatch.png` を使ってください。記事専用に作った 1200×630（OGP 標準比）の画像で、
  SNS シェア時の `og:image` にもそのまま使えます。ファイル名は `sonarqube-for-ide-eyecatch.png` あたりに変えてアップロードするのがおすすめです
  （代替の案：`02-rules.png` も数字が入っていて一覧で目を引きます）
